# Agent Note: 插件组合与生态方案

Status: proposed

[English](2026-08-14-plugin-portfolio-and-ecosystem.md) | 中文

## 问题

DeepSeek Harness 是处于开发者预览阶段的智能体运行时，已经具备持久化会话、工具执行、技能、子智能体、工作流、审批、凭据、遥测和 Web 客户端等强大的本地能力。当前产品缺口不是再增加一个通用聊天或连接器，而是让团队能够发现可信插件、将智能体运行关联到交付结果、设置可复用的组织控制，并衡量插件是否产生足以带来留存和商业化的价值。

证据存在重要边界。仓库提供 GitHub Discussions 和 `/feedback` 命令，但反馈包明确没有聚合检索、分类或分析界面。本方案没有可验证的公开高频投诉数据集。因此，下列优先级是有代码事实支持的产品假设，并非对投诉数量的声明。首批发布必须在定价或扩展路线图之前完成埋点和验证。

## 调研发现

### 产品与用户证据

| --- | --- | --- |

目标用户分为三类：（1）重视快速本地自动化和免费复用套件的个人开发者与开源维护者；（2）愿意为可重复交付、成本可预测和控制能力付费的工程负责人及平台团队；（3）需要私有知识访问、审计证据和管理员策略的受监管企业。第一类带来采用和模板，后两类支撑路线图。

## 方案

### 组合规则

每个候选插件均为独立版本包；当角色独立演进时，必须声明服务定义、提供方和消费者。它必须拥有边界明确的数据所有者、可逆的安装/禁用路径、显式权限、外部操作的审计事件，以及在适用时可免费降级的模式。插件不得从浏览器读取明文密钥、绕过 `ctx.approval` 或修改智能体循环。共享的团队控制平面负责身份、策略、权益和指标；功能插件通过类型化接口消费它。

### 商业模式与验证

商业模式采用开放核心并以结果为导向。本地执行、个人技能、公共套件、基础策略模板和小额度个人工作流保持免费，以保护开发者采用。团队价值以每名活跃受管用户订阅销售，并包含受治理运行；高成本的模型、搜索和连接器消耗以透明转嫁或预付 credits 计费。企业价值按年且与部署绑定：SSO/SCIM、私有注册表、私有连接器、留存、审计导出和支持。

价格调研只支撑测试，不构成上线承诺。可测试每名活跃 Team 用户每月 15–20 美元，并与公开的个人每月 10 美元和受管席位每月 19 美元锚点比较；试点必须证明每名用户每月至少避免一次事故或节省两小时。定价固定前完成 15 个设计伙伴访谈、30 个受控任务测试和为期四周的埋点试点。按个人、创业团队和受监管企业分别分析，不把它们平均为单一的付费意愿数字。

| 运营领域 | 政策与流程 |
| --- | --- |
| 提交与审核 | 发布者验证身份，并声明数据类别、权限、网络目标、凭据引用、许可证、支持负责人、兼容范围和回滚行为。自动检查验证清单 schema、依赖/SBOM、恶意软件特征、密钥扫描、包可复现性、权限差异和真实组合测试。外部写操作、代码执行、浏览器 UI、遥测导出或高权限必须人工审核。 |

| 组合治理 | 每月组合评审按激活、留存团队、交付结果、扣除模型成本后的毛利、支持负担和安全事故排序插件。连续两个季度低于激活与留存阈值的插件，进入修复、免费/社区维护或提供导出与迁移支持的下线流程。 |

## 验收标准

- P0 范围保持为三个可独立安装的包加共享控制平面协议；业务功能不得嵌入智能体循环。
- 每个 P0 包在稳定发布前都发布威胁模型、数据流清单、权限清单、回滚测试和无密钥真实组合场景。
- 市场为每个包记录发布者、产物摘要、兼容性、权限、安装状态和回滚目标。
- 交付、治理以及知识/插件运营产生已脱敏且可归属的结果事件；原始会话记录不能默认成为商业指标。
- 设计伙伴试点在定价离开实验状态前，为本方案指标产生采用前与采用后的测量结果。

## 风险

- 在缺少明确安装格式前建设市场，会形成不安全且不兼容的目录。缓解：先交付声明式签名清单和兼容性检查，延后任意代码包。
- 团队控制可能降低个人采用。缓解：保留本地优先免费层，只对受管工作区应用策略。
- 连接器范围过大可能稀释可靠性并泄露数据。缓解：每个待办任务首发一个提供方，要求来源归属与出站审计事件，只在留存证明价值后扩展。
- 消耗计费可能产生意外账单。缓解：高成本工作前预留预算，展示运行前估算，限制单次与月度支出，并保留人工审批路径。
- 缺少经验证的投诉语料可能误排优先级。缓解：将 P0 试点与产品遥测作为发布要求，并以证据修订组合，而不是固守初始排序。

## 备选方案

**先构建广泛连接器市场。** 这能最大化目录数量，但会重复通用 MCP 分发，并且无法解决信任、结果和管理问题。本方案从可信分发和三个结果导向套件开始。

**只为模型访问变现。** 模型毛利波动大，且无法区分 Harness。共享工作流、治理、证据和私有知识创造持久团队价值，同时允许模型用量保持透明转嫁。

**默认让智能体自主执行。** 当前产品有意采用一次性审批和默认拒绝行为。交付与安全插件保留人工检查点；无人值守自动化是另一个受治理的未来姿态。

**立即构建托管多租户平台。** 当前 Web 服务器以 loopback 为重点，且缺少必要的身份与网络控制。首个商业层保持可部署在本地 Harness 实例旁；托管管理仅在身份、授权和审计基础能力被验证后开展。
