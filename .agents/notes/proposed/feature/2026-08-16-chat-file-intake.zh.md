# Agent Note: 聊天对话从宿主目录引入文件

Status: proposed

[English](2026-08-16-chat-file-intake.md) | 中文

## Problem

Web 输入框能够接收浏览器提供的图片，但用户不能查看宿主目录，也不能把会话工作区中已有的文件添加到对话。现有工作区目录选择器用于选择一个工作区目录；它只列目录、向其 GUI 消费方发布绝对路径，且不会授权将文件内容暴露给模型。图片附件存储只接收不可变的光栅图片。将其中任一机制直接改成通用文件读取，会让模型可见消息依赖可变的宿主路径、绕过附件生命周期，或意外把目录导航变成持久权限。

该功能必须让用户选择相关文件，而不让模型获得发现或读取目录的权限。已选择文件在源文件修改或消失后仍须可回放，须遵守部署可配置的限制，并在选择器或输入框开启时于所有内置主题中保持一致的渲染。

## Proposal

为 Web profile 交付一条完整的聊天文件引入能力。它在输入框增加明确的“添加文件”操作、宿主支持的目录浏览器和持久文件内容块。首个版本接收配置允许的 UTF-8 文本与源代码格式，以及现有图片附件能力已接收的图片格式。它支持从目录中选择单个文件，不支持添加目录或递归展开目录。

用户流程如下：

1. 输入框以会话工作区为根目录打开文件选择器。部署可通过明确确认的“其他目录”路径提供外部目录。
2. 浏览器展示有界、按名称排序的目录和文件行。用户选择一个或多个文件，并看到经清理的展示名称、类别、大小及任何确认要求。
3. 宿主返回短生命周期的选择授权，而非宿主路径或文件字节。输入框将这些授权与已有图片草稿一同渲染为可移除的文件卡片。
4. 发送时，宿主重新校验每个授权，读取确切的已选目标，校验整个批次，提交不可变对象，随后才追加用户消息。
5. 文本文件成为持久 `file` 内容块。图片文件走现有持久 `image` 块。提供方适配器接收每个生成的块或明确拒绝消息；它们都不得静默省略文件。

### Scope and exclusions

| 首个版本包含 | 首个版本不包含 |
| --- | --- |
| 浏览会话工作区和配置允许的外部根目录 | 递归添加目录、目录归档和 glob 选择 |
| 多个 UTF-8 文本/源代码文件及 PNG/JPEG/WebP/GIF 图片 | PDF、Office、音频、视频、压缩包、可执行文件和任意二进制文件 |
| 文件卡片、移除/重试状态、键盘导航和本地化文案 | 将宿主目录文件拖入浏览器、文件全文搜索和选择器中的内容编辑 |
| 持久回放、恢复、fork、导出和明确的提供方处理 | 让模型工具列出或读取未选择的宿主文件 |

### Package topology

| 包或接口 | 职责 |
| --- | --- |
| `packages/attachment/file-attachment` | 定义 `ctx.fileAttachments`、不透明文件 id、经校验的文本文件读取、限制和稳定失败。 |
| `packages/attachment/file-attachment-local` | 在 Harness home 下将已接收的 UTF-8 文件字节保存为内容寻址的不可变对象，并在读取时校验元数据。 |
| `packages/host/file-picker` | 定义宿主文件选择器能力：有界目录/文件列表、选择授权和原生或浏览式交互联合。 |
| `packages/host/file-picker-native` 和 `packages/host/file-picker-browse` | 实现操作系统文件选择和应用内浏览，不向模型或客户端消息内容暴露原始路径。 |
| `packages/host/apiproxy` 和 `packages/client/connection` | 增加会话作用域的选择器 RPC、类型化授权负载、提示词输入部分和宿主侧准入。 |
| `packages/llm/llm` 和每个提供方适配器 | 增加提供方无关的 `file` 内容块，并将经校验的文本渲染进提供方请求或明确拒绝它。 |
| `packages/client/ui-attachment` | 在图片卡片旁增加可复用的文本文件卡片；它仍是只负责展示的原子包。 |
| `packages/client/ui-conversation` | 拥有输入框状态、选择器启动、本地化标签、发送/重试行为和历史渲染。 |

`file-attachment` 与图片附件存储是不同的能力 seam。文本文件对象的媒体校验、内容提取和提供方投影不同于光栅解码；保持规则分离可避免把仅适用于图片的方法扩展为松散类型的二进制存储。文件选择器也不同于工作区目录选择器：它的选择授权是用户对文件快照的授权，不是工作区创建或通用文件系统权限。

### Selection grants and host RPC

文件选择器返回 `FileSelectionGrant`，其中包含不透明 id、经清理的基名、存在时的工作区相对展示路径、声明的类别、字节数和版本指纹。它绝不返回规范化宿主路径。授权绑定一个会话、一个已连接客户端、确切的规范化目标和授权该选择的选择器配置。它会在移除、成功发布、会话 dispose、客户端断开或超过配置生命周期时失效。

网关暴露三个会话作用域操作：一个打开或列出选择器层级，一个切换当前目录或请求外部根目录确认，一个为所选文件行创建授权。提示词输入联合增加 `{ type: 'host-file', selectionId }`；它不携带文件系统路径、base64 字符串或浏览器 `File`。网关拒绝来自其他会话或客户端的授权、过期或已消费的授权、指纹已变化的目标、目录、逃出配置根目录的符号链接，以及不再匹配所选类别的目标。

浏览提供方必须使用配置的文件访问策略和规范化目标。它按稳定名称顺序列出直接子项，使用可配置条目上限，并如实标记 `truncated`。它的行只携带导航和选择所需的数据。原生提供方可以接收操作系统选择的目标，但在目标变为可选之前会发出相同的授权并应用相同的根目录、类型、指纹和确认规则。两个提供方都不向模型可见内容发布路径。

### Durable content and model projection

文件附件存储只接收配置允许的 UTF-8 文件类别。它在解码前校验字节限制，拒绝无效 UTF-8 和带 NUL 的二进制内容，记录经清理的展示名、媒体类型和字节数，并以内容寻址 id 保存原始已接收字节。`readText(ref)` 会重新校验摘要和已存元数据，然后返回精确解码的文本。它不会对历史读取重新应用准入限制，因此后续收紧策略不会让有效会话无法回放。

`dsh-llm` 增加带 `file` 标签和持久文件引用的提供方无关 `FileBlock`。事件日志记录该块，绝不记录所选路径或临时授权。每个适配器在其已声明的内容转换路径中接收该块：首个版本从已校验的存储字节生成确定性、有标签的文本段。不能提供该文本的适配器必须返回 `UNSUPPORTED_CONTENT`；不得展平、省略文件或用路径替代文件。压缩将同样的内容提供给选定路由；若该路由不能接收它则明确失败。在发货组合包启用该块前，历史、会话导出、fork 和 ACP 都须增加明确的文件表示。

从目录选择的图片不会创建文件附件。完成授权校验后，它们进入[图片附件决策](../../implemented/feature/2026-07-22-web-multimodal-image-input-and-durable-attachments.md)中的现有图片批量校验和 `ctx.attachments.saveImage` 流程，保留其模态检查、图片限制、持久引用和历史查看器。混合提示词保持用户选择的文本、文件和图片块顺序。

### Admission, limits, and sensitive data

所有部署可变规则都是已校验配置，在执行前解析，并投影到输入框以便本地预检查。文件附件配置拥有最大文件数、单文件字节数、原始字节总数、解码文本总字节数、允许的文本媒体类型和展示名长度。文件选择器配置拥有浏览条目上限、允许根目录、外部根目录可用性、授权生命周期、符号链接策略、隐藏行策略和需要额外确认的模式。基础组合包通过 Cordis 配置提供明确默认值；消费方代码不得在发送或读取方法内隐藏回退限制。

宿主准入是权威来源。它取得每个获授权目标，校验新鲜度和授权，在写入任何新持久对象前读取并校验所有成员，随后按提交顺序提交。畸形、过大、不可读、已变更、不支持或未确认的成员不会追加用户事件。后续存储失败可能留下已去重、未被引用的对象；引用感知的回收仍是独立工作，不会回滚删除另一个已接收消息可能共享的对象。授权仅在所属用户事件发布后消费，因此短暂失败可在它仍有效时重试。

文件名规则用于帮助用户审慎披露，并非秘密检测器。匹配敏感名称模式的文件要求逐文件明确确认，且宿主校验该确认；普通选择仍是主要授权。选择器声明已接收内容会发送给当前选择的模型提供方。它不扫描文件内容寻找秘密、不声称文件名安全，也不提供模型可用于获取更多数据的路径。

### Composer, accessibility, locale, and themes

当文件选择器能力已组合时，输入框增加一个带标签的“添加文件”控件。对话框具有焦点陷阱，在关闭时将焦点还原给启动控件，将目录和文件行暴露为可用键盘操作的控件，播报选择数和校验变化，并且只在需要等待的选择器操作期间禁用提交控件。文件卡片显示名称、类别、大小、移除操作和可重试的准入失败；它们与图片卡片按用户选择顺序排列。未发送授权只是实时会话状态，不会跨越重新加载、会话切换或 dispose。

`ui-conversation` 拥有中英文消息，并向 `ui-attachment` 原子组件传入已解析标签。展示包遵守 [Web UI style reference](../../../../docs/web-styling.md)：CSS Modules 使用已有 `--dsw-alias-*` 语义 token，不使用字面调色板值，不添加功能级深色选择器，并保持焦点和减少动态效果行为。因此，选择器模态框、文件卡片、敏感数据确认、悬停/焦点状态、禁用行、错误和加载骨架必须在活动偏好于 `light`、`dark`、`system` 和 `glass-obsidian` 间切换时保持可读；实时主题切换会保留打开对话框的状态和选择，因为组件不拥有任何色彩方案状态。

### Delivery slices

1. 构建 `file-attachment` 及其本地提供方、`FileBlock`、适配器转换、持久投影/历史/导出支持和聚焦的符合性测试。在每个已组装消费方都能显式渲染或拒绝新块前，不启用浏览器入口。
2. 增加宿主文件选择器 seam、浏览和原生提供方、不透明授权 RPC 和宿主批量准入。通过组合包配置项将它置于后面，并证明直接 RPC 调用者不能替换路径或授权。
3. 增加输入框对话框、文件卡片、本地化文案、主题 token 样式和状态机集成。在同一有序栏中包含图片授权，同时保留现有粘贴/拖放行为。
4. 增加可运行的 Web snapshot 场景和真实服务器浏览器演示，覆盖选择、移除、发送、重新加载和主题切换。实现从提案转为已发货决策时，更新包 README、附件子系统参考、能力图、配置目录和活跃 Agent Note。

## Alternatives considered

**扩展工作区目录选择器。** 不采用，因为它存在的目的是选择工作区目录，且有意不列出文件。把文件读取加入其面向路径的浏览协议会混合工作区设置和模型数据授权，并暴露比聊天消息所需更多的路径信息。

**附加源路径并在每次模型请求时重新读取。** 不采用，因为后续编辑、删除、符号链接变化或恢复的会话都会改变模型所见内容。不可变内容寻址存储加上已记录的文件引用，使回放、fork、导出和模型请求具有确定性。

**将已选文件作为浏览器 base64 上传。** 不采用于宿主目录选择，因为浏览器可能远离宿主文件系统，却会需要它本不拥有的原始文件字节和路径。宿主授权将文件 I/O 和授权保持在宿主侧，同时保留现有浏览器来源图片的上传路径。

**将目录浏览做成模型工具。** 不采用，因为任务是用户定向的上下文共享，而非 agent 文件系统发现。模型可见工具会引入更广泛的权限、反复确认决策和与一条明确用户消息无关的审计记录。

**将每个文件存入图片附件 seam。** 不采用，因为图片解码、像素策略、二进制读取和原生视觉转换不是文本文件语义。专用 seam 让每个提供方和存储约定保持精确，同时两个存储可共用内容寻址实现技术。

## Acceptance criteria

- 用户能够浏览会话工作区，选择配置允许的文本文件和支持的图片，移除任一选择，并发送一条混合消息；文本记录、RPC 提示词负载、会话事件和提供方请求均不暴露绝对宿主路径。
- 选择后被修改、删除、替换、移动或变得不可读的文件会在持久化前被拒绝；用户得到可操作的重试状态，且不存在部分消息事件。
- 成功的文件消息在重新加载、恢复、fork、压缩输入和导出后保持一致；删除或修改原始宿主文件不会影响其模型可见内容。
- 模型适配器要么接收精确的已存文本投影，要么以稳定的 unsupported-content 失败拒绝请求。任何适配器、压缩路径、历史渲染器、ACP 客户端或导出路径都不会静默丢弃 `FileBlock`。
- 限制、文件类别、敏感名称确认、授权生命周期、根目录范围、隐藏行、符号链接处理和浏览上限均可配置，且在宿主侧权威检查。
- 对话框和卡片可用键盘操作，具备中英文文案，正确保持焦点，并在 `light`、`dark`、`system` 和 `glass-obsidian` 中保持可读和可用，包括选择器开启时的实时偏好切换。
- 聚焦的 seam、网关、适配器、客户端状态和 CSS/组件测试覆盖成功及每一种拒绝类别；无密钥的已组装 Web snapshot 和真实服务器浏览器 GIF 覆盖用户可见流程。

## Risks

文本文件即使字节数较小也可能消耗大量提示词上下文。解码文本总量限制、可见预检查和提供方侧有标签投影控制该成本，但首个版本不包含感知上下文窗口的截断；超出预算的请求会失败，而不是静默截断文件。

目录浏览可能向远程浏览器披露名称和元数据。配置根目录、确切选择授权、可选外部根目录确认和无模型访问可减少暴露，但不能允许任何宿主元数据到远程客户端的部署必须省略浏览提供方，只使用原生选择器。

内容寻址保留会在失败批次或放弃的会话后产生未引用对象。设计不会推测性删除它们，因为去重和 fork 历史使所有权非局部。引用感知回收是一个带有自身持久性设计的后续能力。

首个版本有意不处理二进制文档提取。加入 PDF、Office、压缩包、音频或视频支持需要独立的提取策略、恶意内容和资源限制、提供方表示及用户披露；将这些格式当作 UTF-8 既不安全也会误导用户。
