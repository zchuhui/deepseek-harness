# Agent Note: 应用内目录浏览器作为 Web 默认值

Status: implemented

[English](2026-08-16-web-directory-browser-default.md) | 中文

## 问题

自适应目录选择行会在本地有人值守的 Windows 宿主上选择原生操作系统文件夹对话框。该对话框能确认路径，却不能让浏览器应用展示所选目录的层级，因而难以检查项目目录。

## 决策

`dsh-web-app` 直接挂载成对的 `dsh-host-directory-picker-browse` 与 `dsh-client-ui-directory-picker-browse` 行。Host 列出目录，客户端打开应用内浏览器；操作者可逐层进入文件夹、查看已选文件夹的子项并确认路径。通用 `dsh-host-directory-picker-auto` 包仍供偏好依赖宿主情形选择的组合使用；需要原生对话框的部署会一同替换两条浏览式行。

## 曾考虑的替代方案

- **在 web 组合包中保留自适应选择器。** 否决：它在本地 Windows 上的结果是无法展示应用所需目录层级的系统对话框。
- **同时挂载两对交互。** 否决：每个后端都提供同一个 `directoryPicker` 服务和客户端 `single` slot，重复行会在加载时失败。
- **把浏览器重写为另一套选择器。** 否决：浏览式配对已经提供目录列表、子目录导航、路径面包屑和新建文件夹；另一份实现会复制该能力。

## 后果

随附 Web 与桌面 Web GUI 中的文件夹控件会打开应用内对话框，而不是 OS 选择器。既有的 Miller 分栏会同时展示一个层级及已选文件夹的子层级；面包屑和路径输入支持继续深入。选用操作系统对话框仍是组合配置的选择，而不是运行时回退。
