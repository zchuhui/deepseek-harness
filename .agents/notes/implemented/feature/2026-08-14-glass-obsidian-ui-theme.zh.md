# Agent Note: Glass Obsidian 内置 Web 主题

Status: implemented

[English](2026-08-14-glass-obsidian-ui-theme.md) | 中文

## 问题

Web 客户端需要一个可选的高品质玻璃视觉方案，同时不能改变默认外观、延迟首屏渲染，或把特定主题选择器散落到各个功能 CSS Module 中。

## 决策

将 `glass-obsidian` 作为 `ui-theme.preference` 的第四个内置值。Host 启动脚本与 `ThemePresenter` 都会写入 `body[data-dsw-theme]`，因此已保存的曜石玻璃选择会在 React 渲染前生效，并会在运行时切换后持续同步。新的 `glass-obsidian.css` 负责深蓝色板、半透明语义表面 token、受保护的 `backdrop-filter` 以及不支持模糊的浏览器所用不透明回退。功能模块只消费已有的语义 token 和范围明确的玻璃别名，不再定义另一套色板。

模糊仅用于稳定的应用框架和浮层：应用框架、侧边栏、会话壳、检查器、输入框、菜单、对话框和悬浮卡。消息流行、工具输出和代码块保持不透明，避免在大量滚动内容后重复进行背景合成。曜石玻璃为显式选择；持久化默认值仍是 `system`。

## 验证

聚焦 Vitest 覆盖设置 schema、Host 启动脚本、运行时持久化、外观选择、DOM 主题属性和 Web 样式表顺序。Web 构建和聚焦的文档配对检查覆盖浏览器产物与双语文档。

## 考虑过的替代方案

**单独安装的主题插件。** 外部插件可以注册运行时 token，但当前内置偏好 schema 与 React 前启动脚本无法在没有新增跨包扩展协议的情况下持久化或绘制动态 id。它还需要取得独立组件模块的全局 CSS 所有权。内置产品主题是更小且完整的路径。

**为每个面板和消息应用模糊。** 这会在滚动消息流中产生重复的背景合成，削弱文字对比度，并使工具与代码输出的视觉效果不稳定。限制模糊范围可以维持玻璃层次，而不会让内容沦为装饰。

## 后果

用户可以在浅色、深色和跟随系统之外选择并保留曜石玻璃。后续内置主题可以复用相同的偏好、启动脚本、属性、样式表和 token 路径。第三方插件若要成为可在首屏绘制的正式外观选项，仍需先实现明确的持久化主题扩展。
